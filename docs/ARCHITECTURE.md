# Architecture

Not a Thing is a **design layer on top of stock AOSP Launcher3**, not a launcher written from
scratch. Launcher3 (vendored, unmodified, under `third_party/aosp/launcher3`) owns the home
screen model, app drawer, folders, widgets, drag & drop and settings behaviour. This repo's own
code (`app/`) only changes how things look and adds a handful of first-party widgets.

For the module/directory layout and how the AOSP sources are vendored and updated, see the
[root README](../README.md#project-layout) and [`third_party/aosp/README.md`](../third_party/aosp/README.md).
This document covers what the Not a Thing layer (`app/src/main/java/com/nothinglauncher`) does
and how it hooks into Launcher3.

## 1. How the layer attaches to Launcher3

Launcher3 is designed to be subclassed and themed by derivative launchers; Not a Thing uses
exactly those extension points instead of forking Launcher3's code:

| Extension point | What Not a Thing does with it |
|---|---|
| `Launcher` activity subclass | [`NothingLauncher`](../app/src/main/java/com/nothinglauncher/home/NothingLauncher.kt) overrides theme selection, the long-press menu, and first-run tile placement |
| `SettingsActivity` replacement (`tools:node="replace"` in the manifest) | [`NothingSettingsActivity`](../app/src/main/java/com/nothinglauncher/settings/NothingSettingsActivity.kt) is the entry point for `APPLICATION_PREFERENCES`; Launcher3's own settings screen is still reachable from it as "Advanced home settings" |
| Resource overriding (`res.srcDirs`) | `app/src/main/res-launcher3-theme` (generated by `tools/gen_nothing_theme.py`) replaces Launcher3's wallpaper-derived Material You palette with the fixed Not a Thing monochrome + red palette |
| `CustomWidgetPlugin` / `R.array.custom_widget_providers` | The dot-matrix elements ([`NothingWidget`](../app/src/main/java/com/nothinglauncher/widgets/NothingWidget.kt) subclasses) are registered as in-process custom widgets, so they show up in Launcher3's stock widget picker and are added/moved/resized exactly like any other widget |
| `src_ui_overrides` (`launcher3/src/overrides/java`) | AOSP's designated derivative-extension layer; `PluginManagerWrapper` here is what wires the Not a Thing custom widgets into Launcher3's plugin loading |

Everything else — the grid, drag & drop, folders, the all-apps drawer, notification dots, the
widget host — is stock Launcher3 and is **not** reimplemented or patched.

## 2. `NothingLauncher` (the home activity)

[`NothingLauncher.kt`](../app/src/main/java/com/nothinglauncher/home/NothingLauncher.kt) is a
thin `Launcher` subclass:

- **Backdrop.** `applyBackdrop()` sets the window background to a dot grid
  ([`DotGridDrawable`](../app/src/main/java/com/nothinglauncher/DotGridDrawable.kt)), solid
  black/bone, or the system wallpaper, depending on `NothingPrefs.background`. Launcher3 picks
  its Material You theme from the wallpaper's colours; `setTheme()` is overridden so that when
  the wallpaper isn't actually shown, the theme instead follows the chosen backdrop + night mode.
- **Long-press menu.** `showDefaultOptions()` replaces Launcher3's stock long-press menu with
  [`CustomizeSheet`](../app/src/main/java/com/nothinglauncher/home/CustomizeSheet.kt) (Wallpaper
  & style, Widgets, Settings).
- **First run.** `finishBindingItems()` places the LED clock and battery/calendar widgets on the
  first home screen once, tracked by `NothingPrefs.defaultTilesPlaced`, going through
  Launcher3's normal pending-widget add path.
- **Resume refresh.** `onResume()` refreshes the media and weather elements, since Launcher3
  keeps workspace views attached while home is backgrounded.

## 3. Preferences (`NothingPrefs`)

[`NothingPrefs`](../app/src/main/java/com/nothinglauncher/NothingPrefs.kt) is a small
`SharedPreferences`-backed singleton for state that belongs to the Not a Thing layer only
(backdrop choice, weather city/cache, seconds-ticker toggle, one-time-default flags). It is
**not** where Launcher3's own settings live — grid size, icon style (themed/monochrome),
rotation and notification dots are read and written directly through Launcher3's own
`LauncherPrefs` / `InvariantDeviceProfile` APIs from `NothingSettingsActivity`, so they stay in
sync with Launcher3's stock settings screen.

`NothingPrefs` falls back to an in-memory map if `getSharedPreferences()` throws (seen under
Robolectric/host-side tests), so the rest of the app can treat every getter as non-null.

## 4. Dot-matrix widgets

Each bespoke element is a small `CustomWidgetPlugin` implementation under
`app/src/main/java/com/nothinglauncher/widgets/`, all extending the shared
[`NothingWidget`](../app/src/main/java/com/nothinglauncher/widgets/NothingWidget.kt) base:

| Class | Shows |
|---|---|
| `ClockWidget` | LED dot-matrix clock, date, optional seconds ticker |
| `BatteryCalendarWidget` | Battery dot gauge + day/weekday/next-alarm tile |
| `WeatherWidget` | Live weather via `WeatherRepository` (Open-Meteo, no API key) |
| `MediaWidget` | Now-playing + transport controls via `MediaSessionRepository` (needs notification access) |

`DateTimeWidgetProvider` is a plain system `AppWidgetProvider` (not a Not a Thing element): its
only job is to guarantee the device has at least one installed widget provider, because
Launcher3's `CustomWidgetManager` only registers the in-process custom widgets above when the
system widget list isn't empty.

Rendering primitives shared by the widgets live alongside them at the top level of
`com.nothinglauncher`: `DotFont` (procedural 5×7 glyph rasterizer), `DotMatrixView`/
`DotMatrixClockView`, `BatteryDotsView`, `MediaDotsView`, `WeatherDotsView`, `SecondsTickerView`.

## 5. Icons

[`NothingIconLogic`](../app/src/main/java/com/nothinglauncher/icons/NothingIconLogic.kt) decides
night-mode and re-renders icons when the mono/colour toggle or night mode changes — actual icon
styling (themed monochrome vs. colour) is otherwise Launcher3's own icon pipeline, driven by
`LauncherPrefs.THEMED_ICONS`.

## 6. Build pipeline

```
third_party/aosp/launcher3/   ← vendored, unmodified AOSP sources
         │
         ▼
   :launcher3, :iconloader, :animationlib   ← Gradle modules compiling the AOSP sources,
         │                                     with launcher3/src/{config,overrides}/java
         │                                     providing the platform stand-ins (Flags,
         │                                     BuildConfig) and the override layer
         ▼
       :app   ← com.nothinglauncher: NothingLauncher, NothingSettingsActivity, the dot-matrix
                 widgets, and the generated theme in res-launcher3-theme
```

`./gradlew assembleDebug` / `assembleRelease` build the APK; CI (`.github/workflows/build.yml`)
additionally runs `recordPaparazziDebug` (layoutlib screenshot tests, no emulator) before
assembling. See the root [README](../README.md#building) for signing details and local build
commands.
